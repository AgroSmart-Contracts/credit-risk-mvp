# Bank edition

The bank sees a separate app, built and deployed on its own. Internal code and data are not hidden from it: they are not in the package.

| | Internal site | Bank app |
|---|---|---|
| Source | Repository root | `.bank-build`, generated by `npm run build:bank` |
| Access | `middleware.ts`, shared team credentials | Invite-only accounts in `bank-server/` |
| Data | Full | Finished results from `scripts/bank/build-view-model.ts` |

## Build and check

```bash
npm run build:bank    # fails if an internal module or blocked term enters the package
npm run verify:bank   # attacks the built package locally
```

Deploy only from `.bank-build`:

```bash
cd .bank-build && vercel --prod
```

## Configuration

Internal project: `INTERNAL_ACCESS_USER`, `INTERNAL_ACCESS_PASSWORD` (at least 16 characters). Without them the whole site returns 503.

Bank project: `BANK_SESSION_SECRET` (at least 32 characters) and `BANK_USERS`, a JSON array of entries from:

```bash
npm run bank:add-user -- "Full Name" person@bank.com        # password only
npm run bank:add-user -- "Full Name" person@bank.com --2fa  # password and authenticator code
```

To remove someone, delete their entry and redeploy. Raising an entry's `version` ends its sessions.

## What stays out of the bank app

CRAM, score weights and dimensions, per-risk effects, condition thresholds, full condition list, source names, deal and party names, customs data, coordinates, parcel imagery, maps, and recording of decisions.

The coverage bands (1.50, 1.30, 1.10) and the definition of coverage are visible on purpose: they are terms to agree with the bank.

## Known limits

- Login rate limits are per server instance. Use managed sign-in or the bank's SSO for the pilot.
- The portfolio is illustrative and labelled as such on every page and report.
